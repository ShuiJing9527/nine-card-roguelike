# 悬停列表越界修复

2026-10-26，Unity 6000.0.66f2。

## 根因与复现

原 `BuildBattlePage` 的第91行使用 `sequence[index]` 作为悬停内容的一部分。循环里已有 `int index = i`，不是循环变量错误捕获，也不是用手牌下标直接访问排谱。

问题在于只在 PointerEnter 时检查 `index < sequence.Count`，随后保存了一个延迟求值的 `Func<string>`。`UpdateHover` 第215行每帧继续调用它。在鼠标离开提示的0.15秒宽限内，点击移除会缩短 sequence；原函数继续读取旧位置，造成越界。若重排但长度不变，则会错误地切换到另一张卡。

隔离副本中先运行旧代码：排入3张卡，悬停第3槽，移除第3槽。`hover-before-fix.xml` 中该回归用例按预期失败，日志复现出用户提供的完全相同的 Layout.cs:91 / Layout.cs:215 堆栈。

原工程的 Unity 编辑器处于打开状态，未关闭该编辑器，也未移除它的锁文件；验证在临时项目副本中完成。

## 修复

- `BattleDemo.Layout.cs / BindSlotHover`：进入槽位时绑定实体卡ID。延迟内容只使用这个ID，不再按旧槽位取另一张卡。每次求值前验证该槽位仍属于这张卡；失效则关闭提示。
- `BindHandHover`：直接绑定实体卡ID及武器ID，手牌详情不依赖未来的武器列表位置。排谱变化可以更新其角色说明，但不会换成另一张卡。
- `HoverScopeValid / InvalidateHoverBindings`：给回调绑定页面代际、战局及源视图。重试、返回选择、重建页面和销毁时先清除悬停状态、撤销旧绑定，再重绑新页面。即使原视图对象被复用，旧回调也不能重新打开提示或关闭新提示。
- `RememberComposition`：排谱修改后立即检查当前悬停绑定，避免同帧移除/重排后的旧内容继续存活。
- `UpdateHover / HideHover`：先验证再读取内容；关闭时先清除内容函数、有效性函数、源对象、进入状态和延时状态，再停用面板，避免停用回调重新修改状态。
- `BattleHover`、`HandCardInteraction`：停用时通知悬停结束，销毁时清理委托。保留鼠标进入可滚动详情面板时的宽限行为。

没有捕获并吞掉越界异常，也没有把旧下标强行限制到新范围。无效槽位会关闭提示，不会退回显示邻卡。

## 验证

- PlayMode：20项全部通过（`hover-playmode.xml`），包括新增6项悬停生命周期用例与原14项界面、战斗及逐段表现回归。
- EditMode：57项规则/资产回归通过（`hover-editmode.xml`）。
- 新增用例覆盖：最后一槽移除、删除前面槽位导致下标移动、等长重排、清空后换卡、九张手牌逐一悬停、同一手牌添加/移除后仍显示自身、重试后手动调用旧进入/退出/提示面板回调、返回并切换武器、源视图停用，以及鼠标进入详情面板继续阅读后源视图失效。

本次仅调整悬停绑定及清理，布局、资源、战斗公式和数值保持原样。人工验收：停止后重新Play，悬停排谱尾槽再移除；悬停1号位再重排；清空并排入另一张卡；重试和切武器后再次悬停。提示应在绑定失效时关闭，重新进入后显示当前实际卡牌。
