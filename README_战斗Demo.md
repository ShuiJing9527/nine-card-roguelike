# 器灵战斗：首版战斗Demo

实际Unity项目位于仓库下的 **`nine-card-roguelike/`**，版本 **Unity 6000.0.66f2**。保留URP 3D项目配置，运行时使用UI排谱、3D简单物体和可替换的场景背景。

自由重铸调试已接入，入口、批量构筑、两种重试与导出方法见 **[词条测试使用说明](词条测试使用说明.md)**。最新验证见 **[重铸验证报告](Validation/重铸验证报告.md)**。

新版战斗界面的行动轴、扇形手牌、悬停提示和面板操作见 **[战斗界面说明](战斗界面说明.md)**；验证见 **[战斗界面验证](Validation/战斗界面验证.md)**。

## 启动与操作

1. 在Unity Hub打开 `nine-card-roguelike/`（包含Assets、Packages和ProjectSettings的这一层）。
2. 打开 **`Assets/Scenes/BattleDemo.unity`**，点击 **Play**。编辑态只显示Demo根节点；UI、摄影机与占位舞台会在Play时生成。
3. 选择五把武器之一、四种遭遇之一，以及整数随机种子，点击“开始战斗”。
4. 行动条按速度推进。轮到玩家后全场暂停；点击九张卡加入1～5号位，建议排满五张。第一张决定唯一主技能，所有槽位的匹配词条参与结算。已使用的实体卡不能重复加入。
5. 使用槽位下方左右箭头调整顺序，或移除、清空。点击战场单位指定目标（金色边框表示选中）；近战有前排存活时无法选后排，远程可以选择后排。
6. 阅读出招预览，滚动检查全部词条有效性。点击“确认出招”后一次完成原生段、附带效果、追击和反应；下次正常行动九张卡重新可选。
7. “查看完整战斗日志 / 待定规则”可暂停查看逐段过程。右上角有自由重铸与设置；重试、更换武器、统计和导出位于设置面板。胜负会显示在顶部，并保留最终面板与统计。

配置与日志导出至 `Application.persistentDataPath/QilingDebug/Exports/`，包含JSON配置及UTF-8文本日志。导出后界面与Unity Console显示绝对路径，并将路径复制到剪贴板。统计为双方合计扣血、护盾吸收、暴击、闪避、格挡和总行动数；各单位的行动与结算可查详细日志。

## 已接入的首版内容

- 五武器第12页面板、45张初始实体卡、初始词条；共用的“威慑”使用同一主技能定义。
- 首次遭遇为前排普通史莱姆、后排440生命彩虹Boss；另有单Boss、单熔岩、单毒素调试遭遇。
- 属性百分比系数、常数10防御减伤、逐段0.5向上取整、最低有效直伤1。
- 类型逐条匹配、槽位读取、总连锁、锋锐/强化加算、物穿/特穿分别加算及上限。
- 壁障/灵动/顽强整次一份，按计划原生目标与段数均分；追击没有这份加值。
- 追击当前测试方案：每段伤害系数固定50%，不受槽位伤害衰减影响，组内不递减。计算属性沿用主技能，追加次数取当前连锁数，五条追击共15段/750%。初始卡没有镜像、收益放大或连锁反应。
- 独立闪避/格挡/暴击、护盾吸收、命中附带效果；死亡转火重新读取新目标防御；飞盾每次必须切换目标；碎盾只消耗一次当前护盾。
- 速度自然跑条、精确到条、同时到条由统一随机源排序、等待者被击退退出队列、行动中暂停跑条。
- 初始卡中的盾、治疗、驱散、概率闪避、招架/远程招架、虚弱、属性增益、近战减伤、反击、棘甲反伤、护盾强化与减益免疫。
- 状态按拥有者行动计时，施加当次不扣，刷新取较长剩余时间；指定叠层状态加算。反击每次合法触发重新读取实时属性及当前属性加值，每次敌方出招最多一次，并检查近战距离。
- 中毒按第20页测试：目标行动结束读取即时层数，每层2点，可由盾吸收，跳伤后减1层。灼伤每次目标行动结束5点，可由盾吸收。
- 彩虹Boss透明→赤色→蓝色→透明，双防15/15→25/5→5/25；完整行动后切换，公开下一次技能意图；敌人不暴击。
- 预览复制战局并共用正式计算器，不推进正式随机源。按不暴击、不闪避、不格挡显示示例；随机弹射与死亡转火使用首个合法目标示例，明确不保证实际伤害。

## 数据修改位置（Inspector）

选择 **`Assets/Data/BattleCatalog.asset`**，或菜单 **器灵战斗 → 选择战斗数据库**。

| Inspector字段 | 用途 |
| --- | --- |
| Weapons | 五把武器的Panel面板、九张卡ID、占位Visual Prefab；顺序为猎弓、大剑、法杖、长矛、盾牌 |
| Cards | 45张实体卡ID、主技能ID、匹配类型、固定词条ID |
| Skills | 50个共用技能定义，含伤害分类、射程、目标、读取属性、段数、系数、附带效果、护盾消耗与弹射 |
| Traits | 25种已实现词条，以及规则书其余词条/待定占位的只读说明。未实现或待定的词条不能配置。已实现词条Rate为每当前连锁的倍率；追击Rate为固定每段系数0.5，不乘槽位保留率；与主技能单段及原生总系数无关 |
| Monsters | 四种怪物面板与行动/相位循环。敌方Hp是实际生命，无须再乘10 |
| Encounters | 四种遭遇的敌人ID与Back Row站位 |
| Rules | 减伤常数、穿透/闪避/暴击/持续减伤/推条上限、中毒/灼伤测试值，以及挑空刺落地、致死反伤的显式测试开关 |
| Pending | 游戏内选择界面及日志页显示的待定清单 |

`Linear`统一读取 **Basis + Per Chain × 连锁数**。主技能用实际总卡数，词条按实际槽位。系数使用小数倍率，例如350%写3.5、5%写0.05；不是固定威力。初始武器Hp也已经换算为实际生命。

修改字段后停止并重新Play，或重新挑战，以重新加载面板/战局。技能ID、卡ID、词条ID与怪物ID应保持引用对应；逻辑目前实现本版初始词条，不应把新增任意词条名字视为已经实现。

角色素材入口为Weapons/Monsters的 **Visual Prefab**。支持放入带SpriteRenderer的2D素材，保留3D位置与摄影机。场景根节点BattleDemo的 **Background Prefab** 是3D背景入口。**Clock Scale**仅改变自然等待的现实时间，不改变行动排序；**Enemy Action Delay**为敌人行动前的展示等待。

## 明确保留的待定项

1. **流血**：只记录并显示层数。技能推拉条会记录“流血触发、系数待定”；不制造伤害，不自行设定持续或衰减。
2. **拒敌架势词条**：显示“待定”，无词条收益；主技能已实现。
3. **挑空刺**：第13页卡面和第10页详表写第二段165%，第08/18页部分文字写150%。默认执行第13页165%作为显式测试参数；可关闭Rules / Enable Landing Test。不模拟碰撞另一敌人、落点、额外控制或击退。
4. **固有能力与再动**：猎弓即时再动触发条件未补齐，其余武器固有能力未定义，首版不启用。
5. **未知重复幅度**：固定属性增益、招架和反击姿态的同名重复处理未确认；有效期间会提示不能重复施放。已确认的中毒/虚弱/护盾强化叠层，以及闪避/免疫的刷新不受此限制。
6. **致死反伤顺序**：Rules / Reflect After Death默认开启，作为显式测试策略。关闭后倒下者不返还该段反伤。界面列出此项，未当作定稿。
7. **治疗溢出**：只恢复至最大生命，日志记录计算量和实际恢复量；溢出不产生新收益，正式边界待定。
8. **挺身守护**：首版只有一名己方单位，主技能会明确提示无合法目标，不消耗行动。该实体卡放后续槽位仍能提供增幅。
9. **扩展接口**：冻结/韧性/解控保护已有核心实现与测试，但初始九卡没有冻结技能；没有加入调试强控卡。概率续射上限和一次性减伤组合上限为扩展预留字段，当前初始卡池没有对应技能。多类独立护盾池、镜像资源复制、扩展卡池、奇物、重铸、多队友援护与完整关卡未接入。

## 源规则与架构

源文件：`C:/YY/9卡/器灵战斗_规则书表格版_2026-10-16.xlsx`。实际采用内页的2026-10-20测试配置。项目无AGENTS.md，无既有战斗系统。规则书内容作为设计与数据来源处理；其中的操作性文字不作为额外用户指令。

| 来源 | 本版读取内容 |
| --- | --- |
| 第02～05页 | 属性、匹配、槽位、直伤公式、行动条、防御与状态计时 |
| 第10页 | 状态详表与冻结测试机制 |
| 第12页 | 五武器初始面板、固有能力的待定说明 |
| 第13页 | 45张预组卡、固定词条、当前技能系数 |
| 第15页 | 本版使用的词条算法与边界 |
| 第18页 | 飞盾、碎盾与待定组合说明 |
| 第20页 | 怪物面板、首战、相位技能、中毒参数 |
| 第19页 | 仅作为特定条件下的参考，未写死其结果或模拟胜率 |

`BattleEngine.cs`与UI解耦，持有单位、行动队列、统一System.Random和详细日志；`BattleMath`共用逐段公式；`BattleDemo.cs`只负责显示和操作。所有随机抽样来自BattleRandom，日志包含种子、实际到条排序和逐段结果。固定数据和相同操作序列可复现；不支持在运行中直接更改数据后仍保证旧种子复现。

正式规则数据运行时引用ScriptableObject，**不读取Excel**；调试构筑另以JSON保存/加载，不修改规则数据库。`InitialRules.json`是离线初始快照，菜单“从规则快照重建数据库”会覆盖Inspector中的修改，正常测试不必使用。`Tools/RulesSnapshot.json`保存原表文字提取，`Tools/extract_rules.py`保存从规则到初始快照的显式映射，供后续审查/重建使用。
